# Repository guidance for Codex agents

Read `ref/design.md` for teaching intent and scientific boundaries. Read `WORKPLAN.md` for current implementation tasks; do not treat unfinished design statements as already implemented notebook behavior.

- The default working environment is ESBMTK314 rather than ESBMTK.
- Preserve the 00-04 progression: chemistry; TA-free failure and diagnosis; conservative two-layer extension and effective pump; Boudreau-like construction; complete-model experiments. Keep 01/02 learning goals short and distinct from pump attribution, OA/OAE science, sediments, and feedbacks in 03/04.
- Mark observed targets, fitted parameters, independent inputs, conditional predictions, and software/mass-balance checks accurately. Never claim that a fitted DIC gradient validates the pump or that an injection calculated from the fitted state independently predicts 280 ppm.
- Write time-dependent fluxes using `DIC_s(t)` and `DIC_d(t)` and stationary relationships using `DIC_s^*` and `DIC_d^*`. Check flux and inventory units, equal-and-opposite internal transfers, and carbon/TA conservation.
- Keep geometry and thermodynamic settings explicit. The whole-ocean geometry and atmospheric size are independent inputs. For 02, prepare the surface/deep split algebraically from the prescribed pumped ocean/atmosphere inventory ratio 62.4 and the reference DIC values; label this as ratio-derived teaching geometry. Do not tune it against model output or replace the mass-consistent 01 initial carbon inventory. Use one shared configuration for comparable PyCO2SYS and ESBMTK exercises; 01/02 share uniform conditions, while 03/04 retain their benchmark box-specific conditions. Use ESBMTK density consistently rather than unrelated hard-coded densities.
- In 02, supply the first-order pump assumption and let students derive both the expression and numerical value of k. Mask the analytical derivation as well as its code. Students also derive the extra carbon from 62.4 and the actual initial inventory, then insert it into supplied forcing code. Treat the return to the reference state as forcing/conservation verification, not independent validation of the pump.
- Keep diagram-to-ESBMTK mapping educational and follow documented ESBMTK patterns where feasible. For 01–04, the instructor notebooks are the source for generated student notebooks; preserve marked exercise/solution structure and regenerate student copies through `scripts/build_student_notebooks.py` when those notebooks change. The top-level 01/02 notebooks are launchers, not duplicate sources.
- Respect existing user changes in this worktree. Verify relevant notebook edits with conservation checks, student-notebook generation checks, and the applicable tests before claiming completion.
